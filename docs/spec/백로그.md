# 요구사항 대비 현재 상태와 백로그

요구와 완료 조건 번호는 [서비스 기획서](서비스기획서.md), 데이터·작업·보호 설계는 [기술 설계](기술설계.md)가 소유한다. 이 문서는 구현 순서(P1 단계 번호)와 현재 상태, 착수를 막는 결정만 적는다. 검증 결과는 [검증 기록](검증기록.md)에 쌓는다. 항목을 끝내면 상태를 바꾸고, 확정된 결정은 TECH_RULES.md나 소유 설계 문서로 옮긴 뒤 여기서 지운다.

## 판정 요약 (2026-11-14)

- 완료: 로컬 실행 기반(모노레포·웹·API·SQLite·Electron 기본 창·공통 계약·디자인 기초), P1-01~03. 구현 세부는 [README.md 현재 구현 범위](../../README.md#현재-구현-범위)가 소유한다.
- 결정(2026-11-14, 사용자): 1·2차를 하나의 범위로 합쳐 홈서버 단계에서 전체를 구현한다. 포함: 다섯 출처(원티드·점핏 추가)·백엔드·QA 직무, 포트폴리오·경력기술서·Notion ZIP·OCR, 네이버 1시간 주기 조회·기간 선택·과거 범위, 추천·정정 편의(고급 필터·피드백·묶음·제외 복구·잠금·보류). 제외: 마케팅 직무·Gmail(일단 제외), Electron 데스크톱 앱(트레이·알림 포함), 앱 배포·서명·자동 업데이트·Windows, GA4·Discord. 서류는 모두 MD로 변환해 분석(이미지는 OCR), 점핏은 개발 직무만 조회, 별도 2주 시험 기간 없이 실제로 계속 쓰며 진행. 이유는 공개 배포 없이 실제 사용자만 비공개로 쓰고, OpenAI 비용 부담을 없애기 위함. 근거는 기획서 1·2절.
- 결정(2026-11-14, 사용자): 단계와 상관없이 범위 전체를 먼저 동작하는 수준으로 구현한다. 구현 기간에는 OpenAI를 공고 추출 위주로 최소한만 쓰고(판정은 규칙으로 바꿔 호출 절감), 로컬 LLM 전환·모델 측정·세부 조정(P1-10)은 맨 마지막에 한다. 최종 AI는 홈서버 로컬 LLM 하나이며 그때 OpenAI 사용자별 키 기능(P1-08)을 제거한다. 판정 품질 기준은 추천 정답 사례 54/57, 후보 모델 Qwen3 4B, 홈서버 장비는 i7-6700HQ·RAM 8GB 노트북(증설 안 함).
- 결정(2026-11-14, 사용자): 개발은 Mac, 웹·API 빌드와 배포·실행은 홈서버에서 한다. 사설망 접속은 Tailscale 인증서로 HTTPS. 공고 추출 결과는 사용자별로 따로 저장하고 공유하지 않는다(AI 호출·부하가 사용자 수에 비례). 직무는 프론트엔드·앱 개발·디자인·기획·백엔드·QA(마케팅 제외), Gmail은 일단 제외.
- 결정(2026-11-10, 사용자, 유지): 운영자와 초대 사용자만 쓰는 무료 서버, 공고는 갱신한 사용자 자료로만 저장. 초대 인증은 초대 링크+이메일·비밀번호(TECH_RULES.md 신뢰 경계). 추천 판정 초기 규칙은 기술 설계 D절.
- 현재 코드와 차이: AI는 아직 OpenAI(사용자별 키)이고, 자동 수집은 사람인·잡코리아·자소설닷컴 세 곳, 직무는 네 개, 서류는 이력서 하나, 메일은 네이버만이다(README 현재 구현 범위).
- 실제 연동과 저장을 검증하기 전에는 화면 완료를 서비스 완료로 보고하지 않는다. 일정은 사람/기간을 임의로 확정하지 않는다.
- 자동 테스트 범위: README.md 검증 절 기준.
