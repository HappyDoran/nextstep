# nextstep-parallel

병합 담당(사용자 또는 주 세션)이 적용한다. 역할 에이전트는 자기 작업만 하고 다른 역할을 다시 호출하지 않는다.

1. 분해: 요청을 역할별 작업으로 나눈다. 각 작업에 역할·목표·근거 문서의 절·쓰기 범위·선행 작업·완료 조건·검증 명령을 적는다. 쓰기 범위는 docs/AI_AGENT_HARNESS.md의 역할 소유 표를 넘지 않는다.
2. 순서: 다른 역할이 기대는 결정(기획 완료 조건, 공통 계약, 디자인 토큰)을 먼저 확정한다. 확정 뒤 쓰기 범위가 겹치지 않는 작업만 동시에 실행한다. 겹치면 직렬로 돌린다.
3. 격리: 쓰기 작업마다 별도 git worktree와 `<역할>/<주제>` 브랜치를 쓴다. 사업처럼 수정하지 않는 역할은 worktree 없이 실행한다. 작업 지시는 작업 기록 파일로 남기지 않고 실행 도구에 직접 전달한다.
4. 인계: 각 역할은 PR 본문 형식(역할·변경·검증·미검증·다른 역할에 넘길 요청·남은 사용자 결정)으로 종료 보고한다. 넘길 요청은 다음 분해의 입력이 된다.
5. 병합: 선행 작업부터 병합하고 병합마다 README.md의 전체 검증을 실행한다. 충돌은 해당 경로의 소유 역할 기준으로 해결한다. 병합 후 nextstep-review를 적용한다.
6. 보고: 역할별 결과, 실행한 검증, 미검증, 남은 사용자 결정을 합쳐 보고한다. 한 역할의 실패를 다른 역할의 성공으로 덮지 않는다.
