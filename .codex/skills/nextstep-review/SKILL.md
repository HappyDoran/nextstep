# nextstep-review

git diff로 범위를 확인하고 두 기획서의 해당 완료 조건과 비교한다. 변경이 작업 역할의 쓰기 범위 안인지 docs/AI_AGENT_HARNESS.md의 역할 소유 표로 확인한다. 사용자 격리·비밀정보·외부 URL·삭제 경합·정정 재적용·중복 처리 등 변경이 건드린 경계를 살핀다. 재현 가능한 오류는 위치·영향·입력 조건으로 보고한다. 구조 검사만으로 의미적 보안 검토가 완료됐다고 판단하지 않는다. 실행한 검증과 소유 문서의 상태 표시가 일치하는지 확인한다. 이번 변경과 무관한 개인 계정·원격 설정을 조작하지 않는다.
