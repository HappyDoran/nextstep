# nextstep-backlog

docs/spec/gap-analysis.md가 다음 작업을 정한다. 요구와 1차 완료 조건 번호는 docs/spec/서비스기획서_v0.2.md, 데이터·작업·보호 설계는 docs/spec/기술설계_부록.md가 소유한다.

1. 착수: 백로그의 가장 앞선 미완료 단계를 고른다. 앞 단계를 건너뛰려면 이유를 사용자에게 확인한다. 막는 미결 결정이 있으면 착수하지 않고 결정을 요청한다.
2. 범위: 해당 단계의 요구사항과 완료 조건만 구현한다. 범위 밖 개선은 백로그에 새 행으로 남긴다. 요구를 임의 축소하지 않는다.
3. 완료: 완료 조건의 검증을 실제 연동·저장으로 실행한 뒤 상태를 `완료 (검증 근거)`로 바꾸고 판정 요약과 날짜를 갱신한다. 수동 확인이 남았으면 `구현 완료·수동 미확인`으로 둔다. 모의 데이터·화면만으로 완료 처리하지 않는다.
4. 결정: 사용자가 결정하면 결과를 TECH_RULES.md나 기술 설계 부록으로 옮기고 미결 결정 표에서 지운다. 요구 해석이 바뀌면 기획서도 고친다.
5. 하지 않기로 한 항목은 지우지 않고 이유와 결정자를 판정 요약에 남긴다.
